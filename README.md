# 拼多多 AI 客服演示项目

这是 Duncan 的求职演示项目：一个 Windows 桌面电商客服应用，包含拼多多接入代码、Agent/模型客户端、知识库和本地离线对话演示。当前工作区没有配置拼多多账号或模型密钥，因此不能把线上收发或真实模型生成描述成已经验证。

## 演示功能

- 通过 WebSocket 接收拼多多客服消息，并在连接中断时重连
- 使用异步消息队列和处理器链组织消息处理
- 通过 Agent 工具查询商品、检索客服知识和转接人工
- 分开维护商品知识与售后、物流等客服知识
- 使用关键词规则触发人工接管
- 使用 SQLite 保存本地业务数据，SQLAlchemy 管理数据访问
- 配置多个兼容 Chat Completions 的模型服务商
- 使用虚构店铺数据演示知识检索、回答依据、未知问题处理和人工升级建议

## 技术结构

| 模块 | 作用 |
| --- | --- |
| `Channel/pinduoduo/` | 拼多多登录、WebSocket 连接与消息解析 |
| `Message/` | 消息队列、路由和 AI/关键词处理器 |
| `Agent/CustomerAgent/` | Agent 会话、工具执行与模型客户端 |
| `database/` | SQLAlchemy 模型、SQLite 初始化与知识服务 |
| `bridge/` | 消息上下文、回复和发送服务之间的桥接 |
| `ui/` | PyQt6 桌面界面 |

## 本地启动

环境要求：Windows、Python 3.11 或以上、`uv`。

```powershell
uv sync
uv run python app.py
```

启动后在“设置 → LLM 模型配置”中配置模型服务商、模型名称和 API Key。API Key 使用 Windows DPAPI 加密后保存在本机配置中。

无需外部账号即可打开“客服对话演示”，点击页面上的预设问题查看离线知识匹配结果。该模式不会连接拼多多或发送消息；若已配置模型，可勾选“使用已配置模型”，页面会用现有 LLM 客户端生成回答，且关闭 Agent 工具调用。

## 演示前准备

- 当前平台接入实现面向拼多多，需要可用的拼多多客服账号才能演示实时收发。
- AI 自动回复需要可用的模型服务商和 API Key。
- 可先按 [`showcase/README.md`](showcase/README.md) 演示本地检索流程；离线回复不属于 LLM 生成。
- 真实模型生成需要先配置有效 API；真实平台收发还需专用拼多多账号，二者需分别验证。
- 请使用专门的演示账号和模拟业务数据，不要把真实客户对话、Cookie 或 API Key 放进仓库、截图或录屏。

## 面试讲解建议

离线面试演示可以讲解：模拟客户问题 → 按知识触发词检索虚构商品/客服资料 → 显示引用依据 → 生成带依据的离线回复，或在无可靠资料时建议人工核实。配置模型后可展示实际 LLM 回复；平台 WebSocket、Agent 工具调用与发送链路应在另行配置并验证后再声称已连通。

讲解时区分已有代码能力与本次演示实际配置的能力。平台账号和模型 API 属于外部依赖，README 中的架构描述不代表演示环境已经连通这些服务。
