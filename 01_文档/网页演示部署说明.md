# 网页演示部署说明

## 入口与范围

- 在线地址：<https://duncan-maker117.github.io/customer-agent-demo/>
- 网页目录：`02_网页演示/`。
- 发布工作流：`.github/workflows/deploy-demo.yml`。
- 2026-10-22 用户确认保留现有公开仓库，并在同仓库发布 GitHub Pages。

这是独立的静态客服体验：虚构资料、本地规则匹配、模拟人工协同。不调用模型，不连接拼多多，不代表桌面平台收发已经验证。网页的会话、知识修改及操作记录只存当前页面内存，刷新恢复初始状态。

## 发布方式

GitHub 仓库 `Settings → Pages → Source` 为 `GitHub Actions`。

修改网页后推送至 `main`，工作流自动执行：

1. 校验 JavaScript 语法并运行 9 项规则测试。
2. 仅复制 `index.html`、`styles.css`、`app.js`、`engine.js`、`favicon.svg` 到发布目录，添加 `.nojekyll`。
3. 上传 Pages Artifact 并部署到 `github-pages` 环境。

工作流只授予仓库读取、Pages 写入和 OIDC 身份权限；没有模型密钥或平台凭证。

主仓库本身目前公开；“仅复制网页资源”指 Pages 发布产物范围，不表示仓库中其他文件不可见。

## 本地预览与检查

在根目录使用 Node.js 24：

```powershell
node scripts/serve_web_demo.mjs
```

打开 `http://127.0.0.1:4178/customer-agent-demo/`。端口可通过 `DEMO_PORT` 环境变量调整。服务器仅绑定本机，只提供五个浏览器资源文件。

规则检查：

```powershell
node --check '02_网页演示/app.js'
node --check '02_网页演示/engine.js'
node --test tests/web_demo.test.mjs
```

浏览器验收使用 `scripts/check_web_demo.mjs`，需要可导入的 Playwright 和本机 Chrome。可将 Playwright 安装到临时目录，再通过 `DEMO_PLAYWRIGHT_MODULE` 指向其 `index.mjs`，不必给网页增加构建依赖。服务器运行期间执行检查；可用 `DEMO_BASE_URL` 指定公开网址。

检查覆盖商品/未知问题、输入文本安全、人工暂停/恢复、知识修改/新增/搜索、记录导出、刷新重置、四种屏幕宽度，以及无外部请求、无浏览器报错。截图输出到 `demo/web-desktop.png` 和 `demo/web-mobile.png`。

## 后续维护

- 网页使用独立示例资料；调整 `engine.js` 中的条目或规则后同步运行测试。
- 所有资源使用相对路径，适配 GitHub Pages 的仓库子路径。
- `Content-Security-Policy` 禁止网页的外部连接；若未来增加真实模型服务，需要先设计安全后端和访问限制，再调整配置。
- 修复需要回退时，回退对应网页提交并重新发布；不要将真实配置、客户资料或桌面数据库加入网页目录。
