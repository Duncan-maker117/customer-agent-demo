# AI 客服系统网页演示

这是可部署到 GitHub Pages 的静态交互体验，沿用桌面应用的浅色 Fluent 管理布局、导航顺序、表格、账号卡片和设置表单。默认进入“自动回复”。无需 Python、模型密钥或店铺账号。

## 本地启动

在项目根目录执行（Node.js 24）：

```powershell
node scripts/serve_web_demo.mjs
```

打开终端输出的网址。不要直接双击 HTML；ES 模块需要通过 HTTP 加载。

## 实际支持

- 自动回复：一个虚构账号的上线、离线、开始/停止回复及批量状态操作。
- 关键词管理：23 条初始关键词，可新增、编辑、删除及批量导入，校验重复项。
- 账号管理：虚构店铺与昵称的新增、编辑、删除和字段验证；不进行平台登录。
- 知识库：产品/客服知识标签页、搜索、编辑、新增、删除与 JSON 导出。
- 日志管理：本次操作记录、级别/文本筛选、导出和清空。
- 设置：供应商表单、提示词与业务时间的内存保存、校验与重置；密钥输入禁用。
- 三类独立会话：商品咨询、物流时效、售后处理；可自由输入问题。
- 本地关键词匹配、知识引用、未命中及真实订单查询的边界说明。
- 示例知识的搜索、分类、编辑和新增；修改后立即用于后续匹配。
- 模拟人工接管、暂停自动回复及恢复。
- 当前体验的操作记录与 JSON 导出；刷新恢复初始状态。
- 桌面与移动端布局、键盘操作、原生对话框与减少动态效果设置。

## 运行边界

全部店铺、账号、商品和场景均为虚构。账号“上线”“验证”“开始回复”只改变本地演示状态；回答由规则和知识文本组成，未调用大模型。不会连接拼多多、发送真实消息或提供真人客服。输入与修改仅存于当前页面内存，不上传、不写入浏览器存储。

独立对话演示与真实管理流程隔离：关键词维护、供应商选择、提示词和业务时间只用于表单/管理操作体验，不改变本地对话规则；知识内容修改则会用于后续匹配。

该网页不是桌面应用的平台接入实现；不能用静态体验证明真实业务收发已经验证。

## 修改入口

| 文件 | 用途 |
| --- | --- |
| `index.html` | 工作台结构与表单 |
| `styles.css` | 浅色 Fluent 风格、青色按钮、响应式布局与组件状态 |
| `engine.js` | 示例知识、场景及本地匹配规则 |
| `app.js` | 会话、知识编辑、人工接管和记录的页面状态 |
| `management.js` | 虚构账号状态、关键词、设置与确认对话框 |
| `PRODUCT.md` | 网页产品与体验约定 |

网页示例知识当前从桌面演示资料整理而来，独立维护；修改网页资料不会写入桌面应用数据库。

## 检查与发布

```powershell
node --check '02_网页演示/app.js'
node --check '02_网页演示/management.js'
node --test tests/web_demo.test.mjs
```

`.github/workflows/deploy-demo.yml` 在 `main` 的网页文件变化时运行检查并发布。上传范围仅包含六个浏览器资源文件及 `.nojekyll`，不包括桌面源码、运行配置或数据库。

GitHub 仓库设置的 Pages 来源需选择 GitHub Actions。正式网址以成功部署返回的地址为准。
